# FlashNote NextProto 参考整合设计

**日期：** 2026-08-23  
**状态：** 已确认方向，待进入实施计划

## 背景与目标

FlashNote 是面向 macOS 与 iOS 的原生录音、转写和 AI 纪要产品。QS668 / CB08 录音笔的协议行为存在固件差异，已验证的开源项目 NextProto 可作为真实设备行为、协议边界与回归测试的参考。

本设计的目标是：保留 FlashNote 的 SwiftUI 体验、文件资料库、Qwen3-ASR 转写和 DeepSeek 纪要，同时达到 NextProto 已验证的设备能力水平。

## 产品边界

### 采用

- FlashNote 仍是唯一面向用户发布的 macOS / iOS App。
- FlashNoteCore 成为 CB08 协议、设备文件和录音会话的唯一业务实现。
- NextProto 的公开 MIT 源码仅作为协议算法、状态机、测试样例和交互逻辑参考。
- 设备音频先可靠落地到本机资料库，再按用户配置走 Qwen3-ASR 云端或 SenseVoiceSmall 本地离线转写。
- DeepSeek 根据实际全文生成 AI 纪要，纪要与原音频、全文一同保存在同一录音详情页。

### 不采用

- 不把 NextProto 的 Python、FastAPI、Web UI 或微信小程序嵌入 FlashNote。
- 不把 OSS 长期密钥、百炼密钥或 DeepSeek 密钥写进设备固件、协议包或公开源码。
- 不把设备调试工具当作主导航；调试能力仅在“录音笔”页的高级区域提供。

## 分层架构

```
SwiftUI 工作台 / 文件 / 录音笔 / 设置
                │
FlashNote 录音资料库与详情页
                │
设备会话 ───── 音频资产 ───── 转写提供方 ───── AI 纪要提供方
                │
CB08 BLE 协议层（AE20 / AE21 / AE22 / AE23）
```

### 协议层

- AE21 只做完整帧的无响应写入；AE22 与 AE23 保持独立缓冲和独立帧解析。
- 帧校验使用 CRC-16/XMODEM，长度异常与半包/粘包须可恢复。
- 连接后读取电量、容量、固件、认证码、录音状态，并同步设备时间。
- 已连接的设备仅在用户主动进入“录音笔”或“设备文件”时恢复会话；启动 App 不主动触发蓝牙权限。

### 设备文件

- 列表条目保留原始 28 字节数据，以支持设备端精确删除。
- 下载名按 `base.wav → base.opus → 原始截断名` 尝试；只有“尚未收到任何数据且设备返回文件不存在”时才切换候选名。
- 下载以 12 秒无数据超时判断中断。收到部分数据时保留临时文件与偏移量，重新连接后从偏移量续传；偏移量无效时从零重新下载。
- 本地文件使用稳定的录音 ID 命名，页面展示恢复后的 `.wav` / `.opus` 文件名和自适应大小。
- 删除分为“仅删除本机副本”和“删除设备源文件”，均需二次确认；前者同时删除关联全文与纪要。

### 实时录音

- 设备实时流的固定 40 字节 Raw Opus 包写成合法 Ogg/Opus 容器，同时维护可恢复的本地会话文件。
- 设备发送开始、暂停、继续、停止事件时，同步更新 App 录音弹窗；机身按键触发与页面按钮触发走同一状态机。
- 流式转写优先使用 Qwen3-ASR 实时服务；离线或云端未配置时提示并允许保留音频，随后进行文件转写。

### 转写与纪要

- Qwen3-ASR 文件转写使用“本地文件 → OSS 临时上传地址 → 百炼异步任务 → 轮询结果”的链路，适配一小时以上录音。
- SenseVoiceSmall 是明确可选的本地后备引擎，不覆盖用户选定的 Qwen3-ASR 默认路径。
- DeepSeek 只接收已完成的真实全文；生成失败保留全文，不写入模板占位纪要。

## 信息架构与界面原则

- 工作台聚焦“最近录音”和继续处理，不常驻设备控制面板。
- “录音笔”页包含连接状态、设备健康、实时会话、设备文件和高级控制；普通用户先看到连接与录音，调试命令收进高级区域。
- 文件页明确区分“本地文件”和“设备文件”，不再使用 iCloud 文件这一错误命名。
- 录音详情页为音频、全文、AI 纪要的唯一聚合入口，工作台最近内容、文件列表和设备下载完成后均能进入此页。
- 主题设置只在设置页切换，系统授权与本机密码不会因进入普通页面重复弹出。

## 与 NextProto 的兼容基线

FlashNote 以 NextProto 已验证的下列行为作为回归基线：双通知通道解析、WAV 候选名优先、单包 36 字节下载请求、12 秒下载空闲超时、断点续传、分段下载、设备文件删除、Raw Opus Ogg 封装、录音控制、增益设置和真实设备巡检。

代码移植时保留 NextProto 的 MIT 许可声明与必要归属说明；Swift 实现必须有独立测试，不能仅依赖 Python 行为。

## 交付顺序

1. **设备可靠性对齐**：下载续传、删除、容量/状态刷新、录音状态映射、Raw Opus Ogg 封装与真实流会话。
2. **完整内容闭环**：手动全文转写、失败重试、级联删除、详情页跳转与本地/设备文件一致性。
3. **云端规模化**：OSS 临时上传签名服务、Qwen3-ASR 文件及实时转写、DeepSeek 实际纪要、离线 SenseVoiceSmall 后备。
4. **产品化验证**：使用 NextProto 的测试向量和同一录音笔实机对照，覆盖连接、下载、断线续传、转写和删除。

## 验收标准

- 相同设备与文件在 NextProto 和 FlashNote 中均能列出、下载并得到可播放音频。
- 断开下载后，FlashNote 不重复下载已完成数据，并能从正确偏移量完成文件。
- 从设备录音、实时录音、导入本地文件三条路径都能进入同一个录音详情页，查看音频、全文和 AI 纪要。
- 未配置云端服务时，录音保存和设备管理仍可用；配置失败能给出可操作错误，不伪造转写或纪要结果。
- App 启动不请求蓝牙权限；第一次确有设备操作时才由系统处理授权。
