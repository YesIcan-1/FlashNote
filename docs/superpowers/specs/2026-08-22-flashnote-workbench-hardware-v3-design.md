# FlashNote 工作台与硬件闭环设计 V3

- 日期：2026-08-22
- 状态：已确认，待实施计划审核
- 前置文档：`2026-08-18-flashnote-design-v2.md`（产品与 BLE 协议权威来源）、`2026-08-22-handoff.md`（当前实现状态）

## 1. 目标与范围

本轮将 FlashNote 重构为“工作台优先”的 macOS/iOS AI 录音应用，同时完成 QS668/CB08 硬件的下载、进度、录音控制和 OPUS 音频链路。原 App 的功能范围必须保留，但不复刻其功能宫格、导航或视觉布局。

本轮包含：

- 原生实时转写、音视频导入（含批量队列）、同声传译。
- 录音笔远程录音、设备文件同步/下载/转写/导出管理。
- 本地文件与 iCloud 文件的统一文件中心。
- BLE AE22/AE23 双通知通道、设备状态回填、下载任务进度和错误恢复。
- 通过 libopus 解码设备的原始 OPUS 包，并生成可复用的 WAV 转写输入。

本轮不实现 AI 产出工厂、RAG、播客、声纹分离或完整 iCloud 同步后端；仅为文件中心保留清晰入口与数据边界。

## 2. 信息架构与布局

### 2.1 macOS

采用三栏工作台而非原 App 的首页卡片宫格：

1. 左侧主导航：工作台、录音库、文件、设备、设置。
2. 中央工作区：标题和全局搜索、快速开始操作、进行中的声音任务、最近内容。
3. 右侧常驻设备面板：CB08 连接健康度、电量、固件、录音状态，以及开始录音、同步文件、打开设备控制台。

工作台是默认入口，负责回答“现在要做什么”；设备控制台是深入操作页，负责回答“如何控制硬件”。两处只读取同一个 `DeviceViewModel` 提供的设备和任务状态。

### 2.2 iOS

底部标签为工作台、文件、我的。工作台按纵向内容流排布：设备状态胶囊、快速开始横向操作、当前任务、最近内容。设备控制台从设备入口推入，文件中心作为独立标签；不会把桌面三栏机械缩小到手机上。

### 2.3 原 App 功能的新版落点

| 既有能力 | 新版入口 | 行为 |
| --- | --- | --- |
| 实时转写 | 工作台“实时转写”、新建声音任务 | 本机录音和实时转写校核。 |
| 导入音视频 | 工作台“导入音视频”、文件中心 | 多选入队，进入统一任务状态机。 |
| 同声传译 | 工作台“同声传译” | 独立实时会话，原文和译文并列显示。 |
| 录音笔转写 | 常驻设备面板、设备控制台 | 远程录音、保存、同步、解码和转写。 |
| 录音笔文件 | 设备控制台 | 查看、下载、转写、导出、删除。 |
| 云端/本地文件 | 文件中心 | 本地与 iCloud 两个来源统一检索、打开和任务状态呈现。 |

## 3. 设备与音频架构

### 3.1 BLE 传输

`CB08Central` 保持唯一 `CBCentralManager`，但发现后同时订阅 AE22 与 AE23。

- AE21：无应答写入命令。
- AE22：控制应答、文件列表、下载数据、实时音频。
- AE23：按键和录音状态。

`BLETransport` 将控制通知与事件通知分开暴露。`CB08Device` 为 AE22 和 AE23 分别持有 `CB08FrameParser`，防止分包交错污染缓存。设备层对上层发布电量、固件、授权码、录音状态、实时流状态、文件列表和下载会话事件；UI 不解析协议帧。

### 3.2 下载任务状态机

每个设备文件用独立任务状态表示：`queued`、`downloading`、`decoding`、`transcribing`、`completed`、`failed`、`cancelled`。

- 下载进度使用 `CB08FileEntry.size`（设备压缩文件大小）作为分母；不再用预估 WAV 大小。
- 优先请求候选 `.opus`，设备返回“文件不存在”时再请求 `.wav`，最后使用原始截断名。
- 若下载结束帧缺失，保持当前 6 秒空闲完成兜底；结束码 1 才允许候选名回退，其他结束码明确失败。
- 下载阶段允许中止导入；解码和转写阶段允许取消本地任务。
- 连接丢失时，保留已接收数据和任务错误上下文；用户可在恢复连接后重试，避免无说明地丢失工作。

任务状态同时驱动工作台“进行中的任务”和设备控制台中对应文件行，保证一处开始、两处同样可见。

### 3.3 OPUS 解码边界

在 `FlashNoteCore` 增加薄 C 桥接目标 `COpus` 和 Swift `OpusDecoder`，封装 libopus。Swift 上层不接触 C 指针或解码器生命周期。

- 输入：QS668 固定配置的 40-byte 原始 OPUS 包（20 ms、16 kHz）。
- 输出：16 kHz PCM 缓冲区，离线下载再写成标准 WAV。
- 文件下载优先获得压缩 OPUS；解码生成 WAV 后继续调用既有 `FileTranscriptionEngine`，因此云端 Whisper 与后续本地引擎无需知道设备格式。
- 实时路径复用同一 `OpusDecoder`，将 PCM 交给未来的流式 ASR 适配器。本轮把实时流的设备状态和音频解码打通，不承诺在缺少用户 ASR 配置时输出实时文本。
- 解码失败时，记录坏包计数并显示可理解错误；若有 WAV 候选，允许用户退回 WAV 下载转写。

## 4. 设备控制与状态反馈

设备控制台展示电量、固件、录音状态、文件数和连接状态。连接就绪后请求电量、版本、授权码和文件列表；版本应答必须回填 `firmware`。远程开始、暂停、继续、保存以及实时推流各自对应可用状态，不能在设备不具备条件时显示可执行动作。

所有用户可见状态采用阶段性语言：例如“下载压缩音频 42%”“正在解码为 WAV”“正在转写”“转写完成”。失败卡片说明故障阶段，并且只提供“重试”“重新连接”或“查看详情”等可安全执行的操作。

## 5. 模块边界

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| `CB08Central` | CoreBluetooth 生命周期、AE21/AE22/AE23 特征发现和订阅 | 协议解析、业务 UI。 |
| `CB08Device` | 协议帧、设备应答、下载会话、设备命令 | 持久化、转写、视图状态。 |
| `COpus` / `OpusDecoder` | libopus 生命周期、包到 PCM 解码、WAV 输出辅助 | BLE、ASR 网络调用。 |
| `DeviceTranscriptionService` | 下载、候选回退、任务阶段、解码、转写和存储编排 | SwiftUI 呈现、CoreBluetooth。 |
| `DeviceViewModel` | 设备与任务的可观察 UI 状态和用户意图 | 帧、二进制音频、文件 I/O 细节。 |
| 工作台/设备/文件视图 | 在适当位置显示同一状态并发出操作 | 直接持有设备协议对象。 |

## 6. 错误恢复

- 蓝牙不可用或连接失败：保留原因并提供扫描/重连操作。
- 下载无数据或缺失结束帧：先等待空闲超时，再基于候选策略回退或报告失败。
- 下载中断：保留已收数据、文件名和阶段；不把半成品误标为完成。
- OPUS 解码失败：标记坏包和失败位置，允许使用 WAV 回退路径。
- 转写失败：已写出的 WAV 仍保留，用户可重试转写，不重复下载。
- iCloud 不可用：文件中心显示本地来源可用，云端来源标记为暂不可用，不阻塞本地录音和设备下载。

## 7. 验收与测试

### 7.1 自动化

- `FlashNoteCore`：CRC/帧解析、文件列表、OPUS 单包及多包解码、错误包处理、WAV 输出头和采样参数。
- App 测试：AE22/AE23 分流和状态回填；下载进度按压缩文件大小计算；`.opus → .wav → raw` 候选回退；取消、空闲完成、失败和重试；解码后转写保存。
- UI 视图模型测试：控制可用性、阶段文案和工作台/设备控制台状态一致性。
- 回归：`swift test`、macOS 测试与 iOS arm64 构建均通过。

### 7.2 真机 CB08

在关闭厂商 App 的前提下，依次验证：连接、读取电量/固件/文件、开始/暂停/保存录音、下载 OPUS、准确显示传输进度、解码、转写、失败重试、设备文件导出。用 `open` 启动 macOS App，避免 TCC 权限归属错误。

## 8. 非目标与后续

本轮不将 AI 摘要、思维导图、知识库问答、报告、深度研究、播客、声纹分离或完整 CloudKit 同步作为交付阻塞项。这些能力继续遵循 V2，待硬件与核心工作台稳定后分阶段实施。
